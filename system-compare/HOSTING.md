# Hosting the static build

`node build.mjs` writes a plain static site to `dist/` (543 pages plus data, feeds and sitemaps). Any static host
works; what needs setting up is the cache policy below, compression, and routing for the three backend services.

## Cache policy

The rule is simple: a file whose name changes when its bytes change may be cached for a year; everything else must
be revalidated, because its URL stays the same when its content changes.

| Paths | Why | `Cache-Control` |
|---|---|---|
| `/assets/css/*`, `/assets/js/*` | stylesheets and scripts, a content hash in every name (`site.88246ff417.css`) | `public, max-age=31536000, immutable` |
| `/assets/fonts/*` | web fonts, content-hashed (`inter-latin.3100e775e8.woff2`; plus the font licence text) | `public, max-age=31536000, immutable` |
| `/assets/articles/sized/*` | the responsive hero images the pages load, content-hashed | `public, max-age=31536000, immutable` |
| `/data/*.js` | loaded as `/data/<name>.js?v=<version>`; the version is a hash of every generated data file, so any change to any of them gives every data URL a new query string | `public, max-age=31536000, immutable` **if** the CDN keeps the query string in its cache key or is purged on each deploy (Netlify, Cloudflare Pages and Vercel purge on deploy); otherwise `no-cache` |
| HTML: every `/…/` page and `/404.html`; `/sitemap*.xml`, `/robots.txt`, `/llms.txt`, `/llms-full.txt`, `/feed.xml`, `/atom.xml`, `/site.webmanifest` | fixed URLs that name the current hashed assets and the data version | `no-cache` (revalidate every time; send `ETag` or `Last-Modified` so a check costs a 304) |
| Images with fixed names: `/assets/logos/*`, `/assets/research-cards/*`, `/assets/social-preview.png`, `/assets/articles/*.webp\|png` (not `sized/`), `/assets/articles/social/*`, `/brand/*`, `/favicon.svg` | the catalog, `og:image` tags, social-network caches, old shares and browser icon lookups use these exact names, so they are never renamed | `no-cache`, or a short `public, max-age=86400` |
| `/partners-ui.js` | the partner application script kept from the live site, unhashed | `no-cache` |

Why the fixed-name images are not immutable: they can change under the same name. The logos were re-encoded in place
(same look, fewer bytes) and the share images are regenerated by `scripts/make-article-social.py`.

Keep deploying `/assets/articles/crm-clean-data.png`, `/assets/articles/email-ready-to-send.png` and the other files
directly in `/assets/articles/`: browsers now pick the hero from `sized/` (the plain WebP stays only as the `src`
fallback and in JSON-LD, the two PNGs are referenced by no page), but the catalog and links shared on the old site
point at them.

### Example `_headers` (Netlify, Cloudflare Pages)

Both hosts send `Cache-Control: public, max-age=0, must-revalidate` with an `ETag` for every path no rule matches,
which is exactly the revalidation policy above, so only the long-lived folders need a rule. Do not add a catch-all
rule: both hosts merge the headers of every rule that matches a path.

```
/assets/css/*
  Cache-Control: public, max-age=31536000, immutable
/assets/js/*
  Cache-Control: public, max-age=31536000, immutable
/assets/fonts/*
  Cache-Control: public, max-age=31536000, immutable
/assets/articles/sized/*
  Cache-Control: public, max-age=31536000, immutable
/data/*
  Cache-Control: public, max-age=31536000, immutable
```

Copy it to `dist/_headers` after the build. The same rules in nginx:

```nginx
location ~ ^/assets/(css|js|fonts|articles/sized)/ { add_header Cache-Control "public, max-age=31536000, immutable"; }
location ^~ /data/                                  { add_header Cache-Control "public, max-age=31536000, immutable"; }
location / { add_header Cache-Control "no-cache"; index index.html; try_files $uri $uri/ =404; }
error_page 404 /404.html;
```

On S3 + CloudFront: upload the four asset folders and `/data/` with the long `Cache-Control`, everything else with
`no-cache`, and either include query strings in the CloudFront cache key for `/data/*` or invalidate `/data/*` on
each deploy. Keep the previous deploy's `/assets/css/` and `/assets/js/` files for a day if the host allows it: a page
opened just before a deploy still asks for them.

## Backend services (not part of the static build)

- **`/go/*`** — the outbound redirect service (vendor links, `?intent=&from=`, affiliate tracking). Route it to the
  existing service before any static rule and never let the CDN cache it. `robots.txt` already disallows it.
  A host without it needs `node build.mjs --outbound=direct` (README, decision 6).
- **`/api/partners/*`** — the partner application backend used by `/partners/apply/` (same origin).
- **The contact form endpoint** — `contactEndpoint` in `site.config.mjs`, currently
  `https://systemcompare.co.il/wp-json/systemcompare-contact/v1/`, another origin: it must answer CORS requests
  from the site's origin.

## Everything else the host should do

- Compress text with Brotli or gzip: `.html .css .js .json .xml .txt .svg .webmanifest` (WOFF2, WebP, PNG and JPEG
  are already compressed).
- Content types: `.webmanifest` → `application/manifest+json`, `.woff2` → `font/woff2`, `.svg` → `image/svg+xml`,
  `.js` (including `/data/*.js`) → `text/javascript`.
- Directory URLs end in `/` and are served from `index.html`; send unknown paths `/404.html` with status 404 (it
  works at any depth).
- `.planned-routes.json` at the build root is bookkeeping for `scripts/check.mjs --planned`; it need not be uploaded.
- A Content-Security-Policy, if you add one, must allow the inline `<script>` elements (reader preferences in the
  head, JSON-LD, page data, two small list filters) and inline `style` attributes; there are no inline `<style>`
  blocks. After analytics consent the site loads `https://www.googletagmanager.com/gtag/js` and sends to Google
  Analytics; fonts, images and scripts are otherwise all same-origin.
- `scripts/serve.mjs` is a preview server only: it sends `Cache-Control: no-store` and no compression.
